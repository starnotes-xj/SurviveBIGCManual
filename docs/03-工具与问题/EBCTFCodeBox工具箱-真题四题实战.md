## 第一题：RSA 弱模数 p²q + 共享因子（简答 200 分）

题目：已知 A、B 两个用户公钥（na、nb，公钥指数 65537），① 求 A 私钥；② A 发给 B 的密文 C 求明文。

已知线索（题目分析得出）：`na = ps² × q`（ps = 1571007745962441239），两用户**共享素数 q**。

### 工具箱能做的两步（实测通过）

**步骤 1：扩展 GCD 求 q**（页面：现代密码·非对称 → RSA → 扩展 GCD，或搜索"扩展 GCD"）

| 输入框 | 填入 |
|---|---|
| a（十进制） | na 的完整 309 位 |
| b（十进制） | nb 的完整 308 位 |

点转换 → 输出 `gcd(a, b) = 6047107552…`（= 共享素数 q，309 位）✓ 实测命中。

**步骤 2：模幂解密**（页面：现代密码·非对称 → RSA → 模幂，或搜索"快速幂"/"模幂"）

| 输入框 | 填入 | 说明 |
|---|---|---|
| 底数 base | C 的完整 309 位 | 密文 |
| 指数 exp | **私钥 db**（309 位） | 见下方"怎么来的" |
| 模数 mod | nb 的完整 308 位 | |

点转换 → 输出 `✓ base^exp mod mod = 988193086256651455898930830071291535642038419963` → **这就是明文 m**（实测与 Python 完全一致）✓。

### 工具箱边界（这三步要用别的方式）

| 环节 | 为什么工具箱做不了 | 用什么 |
|---|---|---|
| 求 φ(na) = ps·(ps−1)·(q−1) | p²q 是形变模数，工具箱的 `RSA 参数查看` 按标准两素数算 φ，结果不对 | 一行 Python：`phi = ps*(ps-1)*(q-1)` |
| **求私钥 d = 65537⁻¹ mod φ** | 实测 `模逆` op 的参数框把 309 位输入截断到 30 字符 | `python -c "print(pow(65537,-1,phi))"` |
| 求私钥 db（B 用户） | 同上（模数换 nb，φ=(r−1)(q−1)） | 同上 |

## 第二题：国密 SSL VPN 握手流量分析（简答 200 分）

题目：两份国密 SSL（TLCP）握手 pcap，判 ECDHE/ECC、单向/双向认证，并给出数据 1 的 ClientKeyExchange 里计算预主密钥所需的重要数据（65 字节临时 SM2 公钥）。

### 工具箱边界（这题它基本不上场）

23 类能力里**没有 pcap/流量解析**——TLCP record/握手消息切分是 tshark + GMSSL.lua 插件的活。工具箱只在最后一步有用：把抽出来的 65 字节公钥 hex 做**进制/编码转换**（如 hex → base64 对比答案格式）。

### 实际操作（手册工具链）

```bash
# 1. 找服务端端口: ClientHello 的目的端口=服务端端口
tshark -r f.pcap -Y "tls.handshake.type == 1" -T fields -e tcp.dstport      # 数据1 → 10443
#    装了 GMSSL.lua 时 443 被插件接管, 改用:
tshark -r f.pcap -Y "GMSSL.Hello.Type == 1" -T fields -e tcp.dstport        # 数据2 → 443

# 2. 握手序列判单向/双向: 数 13(CertReq)/11(客户端Cert)/15(CertVerify) 是否出现
tshark -r f.pcap -Y "tls.handshake" -T fields -e frame.number -e tls.handshake.type -e _ws.col.Info

# 3. 套件号(选了什么算法): ServerHello(type=2) 里的协商结果
tshark -r f.pcap -Y "tls.handshake.type == 2" -T fields -e tls.handshake.ciphersuite   # 0xe011=ECDHE / 0xe013=ECC

# 4. CKE 临时公钥(65B): 插件字段或手工切
tshark -r f.pcap -d "tcp.port==10443,gmssl" -Y "GMSSL.Hello.ClientKeyExchangeData" \
  -T fields -e GMSSL.Hello.ClientKeyExchangeData
```

工具箱收尾（可选）：把 CKE 的 65 字节 hex 贴进"进制 / 字符集"类做 hex ↔ base64 换算对比答案格式。

### 答案（已实测复盘）

| 小问 | 答案 |
|---|---|
| 1) 描述正确的是 | **c**（ECC 时用 SM2 密钥交换协议；数据1=0xE011 ECDHE 且双向、数据2=0xE013 ECC 且双向，a/b/d 均错） |
| 2) CKE 重要数据 | 65 字节临时 SM2 公钥 `04‖X‖Y`：`04fc57e6dbc62d06…21dace6d` |
| 3) ECC 预主密钥 | **b、e**（16 字节、双方共同产生；对照 RSA 套件=48 字节客户端产生） |
| 4) ECDHE 判断 | **a、e**（U=[(d_A+x₁·r_A)(d_B+x₂·r_B)]G h=1 ✓；不检测证书可 MITM ✓；b/c/d 均不可行） |

## 第三题：Office 文档单字节变换破译（简答 200 分）

题目：加密的 docx"密报"，分析规律、求加密算法、破译明文。**实测答案：算法 = 每字节循环左移 1 位再异或 0x5A（c = rotl₈(m,1) ⊕ 0x5A），明文内容 = `42035533`**。

### 工具箱能辅助的两步

1. **看文件头**（进制 / 字符集 类）：把密文 docx 前 16 字节转 hex——正确 docx 应为 `50 4B 03 04`（PK），实际是 `FA CC 5C 52` → 判定"被加密而非损坏"；
2. **hex ↔ 字节互转**：得到算法后，若想用工具箱验证单字节映射，可把已知明密对（`50 4B 03 04` ↔ `FA CC 5C 52`）贴进进制类 op 做对照。

### 工具箱边界

`rotl⊕常量` 这种**位级复合变换**没有现成 op（XOR op 只有异或、rot 系列只对文本）——映射规律推导与全文件解密用 Python：

```bash
python -c "
d = open('密报.docx','rb').read()
dec = bytes(((b ^ 0x5A) >> 1 | ((b ^ 0x5A & 1) << 7)) & 0xFF for b in d)
open('明文.docx','wb').write(dec)
"
# 明文.docx 双击打开 → 文档内容 = 42035533
```

判定流程（为什么这么想）：文件头≠PK 但文件大小正常 → 是加密不是损坏 → 同结构偏移密文相同 → 位置无关单字节变换 → 已知明文锚（`50 4B 03 04`）反推映射 → 试加法差/异或差都不齐 → 看位结构 → rotl⊕0x5A。完整思路回放见测试平台复盘卷。

## 第四题：MD5 口令破译 + 系统登录（实操 250 分）

题目：已知四组"明文口令↔MD5 密文"推断加密方式；admin 密文 `aa6490394ce8565612fd2d55f346fb7c`，口令 6 位数字，破译后登录 `172.16.8.6:80` 拿 FLAG（15 位数字）。

### 工具箱能做的两步（实测路径）

1. **哈希类型识别**（分析 / 爆破 类，或搜"哈希类型识别"）：贴任一密文（如 `e10adc3949ba59abbe56e057f20f883e`）→ 识别为 MD5 ✓——对应题目"根据明密关系推断口令加密方式"；
2. **MD5 验证**（哈希 / 校验 类的 MD5 op）：猜一组 6 位数字贴进去生成 MD5 对比密文——单次验证可用；**逐个遍历 10⁶ 个候选不要在 UI 里手点**。

### 工具箱边界（爆破交给专业工具）

10⁶ 的 MD5 暴力用 hashcat（离线秒级）：

```bash
hashcat -m 0 -a 3 aa6490394ce8565612fd2d55f346fb7c "?d?d?d?d?d?d"
# 输出 aa6490394ce8565612fd2d55f346fb7c:770713 → admin 口令 = 770713
```

或纯 Python（比赛机兜底）：

```bash
python -c "
from hashlib import md5
print(next(str(i) for i in range(1000000) if md5(str(i).encode()).hexdigest()=='aa6490394ce8565612fd2d55f346fb7c'))"
# 770713
```

拿到口令后浏览器登录 `172.16.8.6:80` → 页面给出 15 位数字 FLAG → 填入答题框。
