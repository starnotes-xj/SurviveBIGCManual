# 网络代理工具（“梯子”）合规使用说明

“梯子”是网络代理工具的口语称呼。本页只介绍网络代理客户端在**合法、合规且获得授权的场景**中的基本概念与本地配置方法，不提供或推荐任何代理服务、订阅套餐、邀请链接，也不构成购买建议。

访问 GitHub、Google、Claude、Docker Hub 等网站是否需要额外网络配置，取决于所在地区、校园网或单位网络策略、运营商以及网站服务状态，不能一概而论。请优先使用目标服务的官方入口、学校或单位批准的网络服务、官方镜像或其他合规替代方案。网络代理工具完全按需自愿使用，不是入学、学习或学校事务的必需条件。

!!! warning "使用边界"
    使用前请确认符合所在地法律法规、学校或单位网络管理规定、网络运营商协议以及目标网站服务条款。不得使用代理工具规避网络安全管理、绕过访问控制、进行未授权访问、侵犯知识产权、实施欺诈或隐藏违法活动。无法确认使用场景是否合法时，请先咨询网络管理员或专业人士。

## 基本概念

**代理服务或配置** = 由本人、学校、单位或其他有权提供服务的主体提供的网络连接配置。使用前应确认来源、授权范围、隐私政策、日志留存、计费和退款规则。

**客户端** = 运行在电脑或移动设备上的软件，按本地配置决定哪些请求通过代理转发。

不同客户端和服务支持的协议、加密方式及日志策略各不相同，请以项目或服务提供方的官方文档为准。不要以规避网络管理、隐藏来源或绕过访问控制为目的选择协议。

## 代理服务或配置的安全检查

如果确有合法合规的网络连接需求，请在使用前核对：

- 服务来源、运营主体和授权范围是否清晰；
- 隐私政策、日志留存、数据处理、计费和退款规则是否透明；
- 配置是否仅要求必要权限，是否要求安装根证书、关闭杀毒软件或提交账号密码、API 密钥等敏感信息；
- 是否符合学校或单位网络管理要求，以及目标网站的服务条款。

不要使用来历不明、要求共享账号、收集过多个人信息或承诺“绕过一切限制”的服务，也不要转发未经核验的订阅链接。

## 配置订阅

如果你已经获得本人有权使用的配置文件或订阅链接，可按客户端官方说明导入：

1. 打开 Clash Verge Rev，点击左侧「**订阅**」
2. 在「订阅文件链接」中粘贴订阅 URL，点击「**导入**」
3. 回到「**代理**」页，选择符合授权范围的配置，并先确认流量去向和隐私设置

**首次配置建议开启以下选项**（在「设置」中）：

| 选项 | 说明 |
|---|---|
| 系统代理 | 仅在确需让浏览器等软件使用代理时开启；不使用时关闭 |
| 开机自启 | 按需开启，并留意软件是否会在开机时自动联网 |
| 局域网连接 | 默认关闭；只有在可信网络中确有共享需求且已获授权时开启 |
| DNS 覆写 | 仅按官方文档和实际故障需要配置，不要随意改变 DNS |
| 统一延迟 | 让延迟数据更准确 |
| IPv6 | 仅在有明确故障证据并了解影响时调整，不作为规避网络管理的手段 |

**代理模式说明：**

| 模式 | 适用场景 |
|---|---|
| 规则模式 | 按已配置规则分流；先确认规则来源和授权范围 |
| 全局模式 | 所有流量走代理；仅在确有授权且了解数据流向时临时使用 |
| 直连模式 | 不使用代理，适合不需要代理或排查本地网络问题时使用 |

## 常见问题

**Q：重启电脑后网络访问不了？**

常见原因是系统代理仍处于开启状态，但客户端没有运行。可以按以下顺序排查：

- 确认客户端是否正常运行；
- 不需要代理时切换到「**直连模式**」，或在 Windows 设置 → 网络和 Internet → 代理中关闭「使用代理服务器」；
- 只有在确认需要且了解自动联网影响时，才考虑开启「**开机自启**」。

**Q：启用网络代理后某些网站还是打不开？**

先检查网址、网站服务状态、当前网络、DNS 和访问权限。不要为了绕过校园网、单位网络或网站的访问控制而切换到全局模式；需要帮助时联系网络管理员或使用目标服务提供的官方支持渠道。

**Q：为什么同一个网站在不同网络下表现不同？**

这类现象不一定是客户端导致的，常见原因是 **DNS 解析、网络出口、代理路由、访问权限或网站端状态**在不同时间和网络下不一致：

- 不同网络通常使用不同的 DNS 和出口线路，同一个域名可能解析到不同的 IP，某条线路可能超时或无法访问。
- 客户端开关会影响本地代理和 DNS；如果浏览器、系统代理或 DNS 缓存没有及时刷新，切换前后的结果可能暂时看起来一样。
- 网站服务器、CDN 或访问策略也可能短时间故障，因此“刚才打不开、后来又能打开”不能证明一定是客户端配置错误。

仅在排查本人拥有或获授权访问的服务时，可以用下面的命令区分 DNS 和本地连通性问题；将 `example.com` 换成目标域名：

```powershell
Clear-DnsClientCache
Resolve-DnsName example.com
curl.exe -I -v https://example.com
curl.exe -x http://127.0.0.1:7897 -I -v https://example.com
```

`ERR_NAME_NOT_RESOLVED` 通常指向 DNS，`ERR_CONNECTION_TIMED_OUT` 更像线路或服务端无响应，`403/429/5xx` 则通常需要查看网站端提示或等待恢复。遇到证书不匹配或浏览器安全警告时，不要直接忽略。

**Q：GitHub clone 速度很慢？**

如确有合法合规的访问需求，可在具体仓库中临时配置 Git 代理，避免影响其他项目：

```bash
git config --local http.proxy http://127.0.0.1:7897
git config --local https.proxy http://127.0.0.1:7897
```

端口号（示例中的 `7897`）以客户端实际设置为准。使用完毕后可移除仓库级配置：

```bash
git config --local --unset http.proxy
git config --local --unset https.proxy
```

**Q：网络代理已启用但浏览器打不开？**

先确认客户端正在运行且「系统代理」状态与当前需求一致；不需要代理时应关闭系统代理。若使用浏览器扩展，请只从官方商店或项目官方发布页获取，并核对权限和隐私政策。

**Q：Windows 端口被占用怎么办？**

先确认端口确实被本人运行的客户端占用，再调整客户端端口；不要结束系统进程或他人进程：

```powershell
# 查看 7897 端口占用
netstat -ano | findstr :7897
# 仅查看进程信息，不要直接结束不明进程
Get-Process -Id <PID号>
```
