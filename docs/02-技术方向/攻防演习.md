# 攻防演习实战纪实：这是一场什么样的活动（新生篇）

> 面向：刚加入战队的新同学、对"实战攻防"好奇的同学。
> 说明：本文基于我校攻击队参加 **2026 年 10 月**一次省级教育系统攻防演习的真实经历整理，**已全面脱敏**——不含任何参演单位名称、系统地址、账号口令、密钥值、漏洞可复现细节与人员信息。只讲：活动长什么样、什么时候打、怎么打、我们能学到什么、哪些红线绝对不能碰。

---

## 一、这是什么活动

**教育系统网络安全攻防演习**，由教育主管部门统一组织的**年度红蓝对抗**：

- **红方（攻击方）**：各高校学生组队代表学校出战，拿到组委会下发的**授权清单**后，对清单内的教育系统发起模拟攻击；
- **蓝方（防守方）**：清单内各单位的安全人员，负责防护、监测、封禁与溯源；
- **性质**：**受控、授权、有边界**的实战演练——打的都是组委会圈定的目标，本质上是一次"真刀真枪但不许越线"的考试。

与 CTF 的本质区别：CTF 打的是出题人构造的靶机，flag 就是终点；这里打的是**真实在用的教育业务系统**，凭据、路径、突破口全靠自己侦察，而且对面坐着活的防守方。

**成绩实况（如实）**：我们这一届共提交 4 项成果，前 3 项（配置泄露+CSRF 绕过、VPN 前端密钥硬编码、演习前挂马发现）全部被评审驳回——只有第 4 项（某平台管理员默认口令验证有效）成立。驳回原因官方未给出明细，复盘认为核心是"证明了机制缺陷但未获取实际权限/数据"。这个真实的成败比，比任何"大佬一穿六"的故事都更接近这项活动的常态。

## 二、什么时候开展（划重点）

| 项目 | 规律 |
|---|---|
| **年度节奏** | **每年一届**，近年固定在 **10 月**举行（2026 年已是第五届） |
| **赛程** | 约 **10 天**，含周末 |
| **每日时段** | **每天 09:00–17:00** 才是合法攻击时段；17:00 后停止一切攻击动作，**夜间 AI 自动化攻击明令禁止（抓到重罚）** |
| **节奏特点** | 前 1–2 天信息收集 → 中段集中打点 → 最后几天补成果、写材料 |

> 想参加：**9 月底~10 月初**组队备战、入队培训；**10 月上旬**拿授权清单；**10 月中旬开打**。建议提前半年练手。报名走专业老师/实验室渠道，以学校为单位组队，每人一个平台账号。

## 三、平台化作战（不是在自己电脑上随便打）

1. **统一接入**：演练专用 VPN，一人一号，进来先登**堡垒机**；
2. **虚拟终端作战**：平台为每人配发攻击主机（Windows/Kali/反弹机各一台），**所有攻击动作必须在平台虚拟终端里完成**——本地电脑只用来查资料、写报告；
3. **出口 IP 制度**：通过平台绑定攻击出口 IP，未绑定不能上网；所有流量从授权出口出去——这是留痕与追责的基础；
4. **成果制**：不是"谁把系统搞挂"，而是谁拿出更多**可验证的成果**——每份成果 = 报告（含凭据来源/利用细节/攻击路径三要素）+ 带时间戳的证据截图 + 全程录屏 + AI 原始日志；
5. **计分**：按权限层级分档（Web 应用/主机/数据库/域控/安全设备/数据等），另有**博弈报告**加分项（记录防守方的封 IP、改口令、下线等应对，写得好一份 2000 分）。

## 四、规则红线（不背下来会出局）

1. **时段**：只打 09:00–17:00；
2. **范围**：只打授权清单内目标，表外系统 = 严重违规；
3. **不破坏**：禁 DoS/ARP 欺骗/DNS 劫持等可用性攻击；不删数据、不改页面；
4. **数据红线**：不下载/保存业务数据；抓取个人信息、成绩等**用于训练 AI 模型**罚得最狠；
5. **AI 合规**：允许辅助，但**只能用国产已备案大模型**（境外模型直接出局）；AI 参与必须全程录屏+导出全部原始日志+报告声明；
6. **痕迹管理**：植入的文件、新增/修改的账号必须登记《攻击痕迹清除确认表》并清理；**凡请求到达过目标，哪怕失败，也要如实登记"尝试未成功"**；
7. **先申报后动手**：钓鱼、供应链、0day、内网隧道、扩大战果，必须先获批。

## 五、实战复盘（我们这一届做了什么）

### 1. 摸清地形：从"纸面清单"到"真实攻击面"

- 对授权范围约 **29000 台主机**分段扫描建立底账；
- 浏览器插件程序化批量提取指纹（React/若依/正方教务/PowerCreator……），据此选武器；
- **DNS 纠偏**：清单标注"内网 IP"的系统，实测公网 DNS 有解析——攻击面比纸面大。信息收集做得细，机会就多。

### 2. 认证面主攻：全库扫描零命中之后

自动化扫描（14000+ 模板）对可达目标**零命中**后，我们判断：教育系统的命门不在"神秘 0day"，在**认证机制的实现质量**。这条线打穿了三个案例，但**结局大不相同**——这个对比才是最值得新生记住的：

- **"伪装加密"破解**：某平台配置接口无鉴权返回"加密"配置，解密函数就藏在页面自带 JS 里——解出密钥后，其 CSRF token 算法（时间戳逐位映射密钥串）被完整复刻，实测可穿透服务端校验层。**技术验证成功，但成果提交被驳回**（业务层仍有会话拦截，未获取数据/权限，评审不认）；
- **教务登录算法还原**：某教务登录流程为"先取一次性种子，账号密码与种子逐位交织后提交"，通过校准实验证实复刻正确。**算法逆向成功，但同样止步于登录墙**，未转化为可计分成果；
- **框架默认口令**：某全市性业务平台使用若依框架，**出厂账号的默认口令从未修改**，经官方登录预校验接口验证有效（接口还返回了账号绑定的脱敏手机号——本身就是信息泄露）。系统在密码后强制短信二次验证，我们在预校验成功处依规停止。

**三者唯一拿到分的，是最后一个。** 复盘差距在哪：前两个证明的是"防护可被绕过"，但绕过之后没有实际权限、没有数据、没有可展示的"权限获取"证据，评审按"未成功"处理；而默认口令是**实打实的有效凭据**（哪怕后面还有短信验证），危害直接、证据确凿（服务端确认口令有效+返回账号信息）。教训：**验证密码正确 ≠ 拿下系统；评审看的是结果与危害，不是你逆向有多漂亮**。选定方向后，优先打"一步就能看到权限"的面（默认口令/未授权访问），而不是需要三步才能落地的机制缺陷。

### 3. 工具与工程：条件受限时自己造

靶场环境装不上数据库客户端（缺认证插件、包管理残缺），就用纯 Python 手写了一个支持 caching_sha2_password 全认证路径（TLS + RSA-OAEP）的客户端——**协议级理解在真实环境里真的能救命**。

### 4. AI 人机协同（以及它的坑）

用国产备案大模型做资产关联、算法逆向辅助、验证码初读、文档整理。实测：**AI 会一本正经地编造"读到的验证码"和"发现的密钥"**——人工逐项复核必须兜底，这也是规则要求（AI 生成的报告不能直接交）。

### 5. 和防守方的博弈（最精彩的部分）

- **出口 IP 封禁**：多家单位把平台出口拉黑（连接黑洞化）→ 平台换绑出口 IP 后全量复测，部分目标复活；
- **DNS 级封锁**：某域名 https 全超时但 http:80 正常——`--resolve` 钉真实 IP 识破"DNS 黑洞"而非防火墙；
- **活防御**：刚验证完默认口令，账号即被"用户已锁定"；现役 WAF 对注入 payload 拦截干净利落；
- **验证码+机器人风控**：专门的机器人检查接口让 hydra/medusa/patator 等爆破工具全部失效——**工具化攻击让位于人机协同低频测试**。

防守越有效，越值得记录——这些动作本身就是博弈报告素材。

## 六、少踩坑的经验（学长学姐的血泪）

1. **信息收集决定上限**：一半以上时间花在"看"——资产测绘、指纹、目录与接口。谁看得细，谁机会多；
2. **登录入口是永恒战场**：动手测弱口令前，先花几分钟判断防护强度（验证码强度/锁定策略/频率限制），有的系统 5 次锁号且按账号计；
3. **"防护设计有缺陷"本身就是成果**：配置接口无鉴权、前端硬编码密钥、加密"只加密了个寂寞"、校验可匿名复刻——**学会读前端代码**，很多分在这里；
4. **写材料占一半时间**：动手之前就想好怎么留痕（录屏、带时间戳截图、台账）；
5. **大部分时间在碰壁**：被封、被拦、连不上是常态。**坚持如实记录，"尝试未成功"也是一种专业**；
6. **双出口/多出口实测**：目标"连不上"未必是死了，可能是只封了你这个出口——换环境复测再下结论；
7. **"机制缺陷"≠"成果"**：证明防护可绕过但没拿到权限/数据的，评审可能不认（我们三条认证线只有一条得分）；选题时优先"一步见权限"的面（默认口令、未授权访问），并在成果里写清**危害可达性**。

## 七、给新生的备赛清单

- **基础**：HTTP 协议、Web 漏洞原理（OWASP Top 10）、Linux 常用命令；
- **工具**：nmap/masscan、nuclei、Burp Suite、浏览器 F12（最好的老师）；
- **一门语言**：Python 到能写"协议级小工具"的程度（批量请求只是起点）；
- **框架知识**：若依/正方/致远/通达等国产系统的常见弱点模式；
- **非技术但重要**：记录习惯、报告写作、合规意识；
- **入队后**：先跟打辅助（记录/截图/整理材料），熟悉全流程再上手打点。

## 八、聊点感受

这是"技术+纪律+表达"的复合型比赛：技术决定你能不能找到入口，纪律决定你走多远，表达决定战果能否被认可。对学生来说，它是极少数能**在授权范围内摸到真实生产系统**的机会——也因此，**合规与敬畏是它的第一课**。

十天里大多数时间在侦察、记录、碰壁、等防守方反应：四个提交三个被驳回，真正立住的只有一条默认口令线。但把一个系统的认证机制从黑盒推导到完整复刻、再看着它被评审打回的过程，比任何 CTF 题都更像真实的渗透测试——**评分标准不是你的技术含量，是危害是否落地**。工具会过时、靶机会重建，但"侦察→假设→验证→记录"的方法论是通用的。
