## 一、这是什么比赛

**信息安全与对抗技术竞赛（ISCC：Information Security and Countermeasures Contest）**，2004 年创建（国内第一），由**北京理工大学、中国兵工学会**主办，至 2026 年已连续举办 23 届，近年参赛院校 2000 多所。**密码安全赛**是 ISCC 的赛项之一，依据《密码法》《网络安全法》等法规设置，聚焦密码在关键信息基础设施、数字政务、金融科技等领域的应用实践。

和 CTF 的关系：赛制上就是"解题得分"的积分赛，体验接近 CTF 的 Crypto 方向；但命题范围覆盖**密码技术全生命周期**（算法 → 协议 → 部署运维 → 合规检测 → 设备漏洞挖掘），比一般 CTF 的密码题更贴产业实操，还包含合规类题目。

## 三、三级赛制

**校级赛 → 区域赛 → 总决赛**，逐级选拔：

1. **校级赛**：参赛院校**必须**进行校级选拔；所有队伍都要在官方报名系统填报；晋级比例不超过 50%，凭校级赛晋级证明参加区域赛。
2. **区域赛**：晋级队伍参加线下区域赛，按积分排名取**前 50%** 晋级总决赛。
3. **总决赛**：线下进行，最终奖项以总决赛现场得分评定。

区域赛与总决赛**独立命题、独立计分**，所以区域赛发挥如何不影响总决赛起跑线。

!!! warning "线下赛报到要带三样东西"
    学生证、身份证、加盖校/院/教务处公章的报名表——缺一样可能影响参赛，提前盖章。

## 四、校级赛：学校自办，组委会只卡三条线

第一次参赛最容易懵的就是这一环节——**校赛比什么、什么时候比，全部由学校自行决定**，组委会不限制形式，不需要用 ISCC 官方题目，自己出题、拿往届题、用校内平台都可以。我们专门发邮件问过组委会，硬性约束只有以下三条：

1. **比例线**：晋级比例**不高于 50%**。报名系统会校验报名队伍数与晋级队伍数的比例关系（答疑原话："系统上必须保证晋级队伍数量 ×2 的总报名队伍"）；
2. **数量线**：每个学校晋级队伍**不能超过 3 支**；
3. **材料线**：**所有**参赛队伍（包括未晋级的）都必须在官方报名系统中填报；晋级证明需要**体现出未晋级的队伍**；晋级队伍必须有校级赛成绩。系统锁定前要把晋级状态改好、材料交齐。

**由此推出的实操结论**（同样是答疑原话拆解）：

- 想让 3 支队全部晋级区域赛 → 需要再找 3 支队伍报名凑基数（6 队 × 50% = 3 队）；
- 只有 3 支队报名 → 按比例最多 1 支晋级；此时学校可酌情决定是否省略校赛阶段，但系统里的晋级状态和材料一样不能少。

!!! warning "系统锁定后无法补救"
    组委会 2026-10-28 邮件原话："现在还来得及，但是周五前必须有晋级结果，修改完晋级状态且提交完三份完整、正确的材料，周五系统就锁定了，无法报名、修改以及材料提交。"也就是说，**校赛打完只是第一步——系统里的晋级状态 + 材料提交才是决定能不能参加区域赛的真正开关**，别拖到截止当天。

### 组委会答疑实录（2026 年 10 月，邮件原文摘录）

> **问**：校级赛的比赛内容也是我们自己决定比什么么？不用拿 ISCC 官方之类的题目来作为测验吗？我们学校报名密码安全赛的队伍只有三队，那 50% 也就是只能有一队晋级是吗？
>
> **答**：是的，比赛内容为学校自行决定。如果你想三队都来，可以再找其他三队进行报名；如果只想三队来、并且只有三队报名，学校可以酌情决定是否省略校赛阶段。但要求系统上必须保证晋级队伍数量 ×2 的总报名队伍，必须满足不高于 50% 晋级比例，且晋级证明需要体现为晋级队伍。
>
> **问**：我们第一次参加，请问什么时候举办校级赛？我们现在还能上传报名表吗？
>
> **答**：校级赛由学校自行安排，我们不做限制。我们唯一限制的就是校级赛报名队伍和晋级队伍都需要遵守"晋级比例不超过 50%"，且每个学校晋级队伍不能超过 3 支。报名系统需要有对应的未晋级的队伍，晋级证明也需要体现出来未晋级的队伍。

## 五、比什么：赛题方向与评分规则

赛题围绕**密码应用实践**，六个核心方向：

- **密码算法原理**——古典密码、对称/非对称加密、哈希、签名的原理与实现
- **密码协议设计**——TLS、密钥交换、认证协议等的设计与分析
- **密码技术部署与运维**——OpenSSL 配置、密钥管理、密码设备使用
- **密码应用合规检测**——《密码法》与商用密码应用安全性评估相关要求
- **密码设备漏洞挖掘**——密码机、加密卡等设备的漏洞分析
- **信息安全攻防**——综合攻防场景

评分规则要点：

1. 提交正确答案后**系统即时判分**，无人工干预；每题唯一标准答案；
2. **上下半场赛制**，各半场独立题集，超时提交一律无效；
3. 积分相同的队伍，按全部有效答对题目的**累计总耗时**排序，用时短者靠前——所以手速和熟练度也是分数。

## 六、奖项设置

按**晋级总决赛队伍总数**计算：一等奖原则上不超过 15%，二等奖不超过 30%，三等奖不超过 35%，优胜奖视情况确定。注意：**同一院校最多 1 个一等奖、1 个二等奖**——若同校多队进入一、二等奖圈，排名靠后的队伍顺延到下一等级。

## 七、备赛建议

- **密码学主线**：古典密码 → 对称加密（DES/AES）→ 非对称加密（RSA/ECC）→ 哈希（MD5/SHA）→ 数字签名 → 密钥交换，按这条线过一遍原理，每步都用 Python 或 OpenSSL 手上跑一遍；
- **工具**：Python（`pycryptodome`）、OpenSSL、Wireshark（看密码协议长什么样）、CTF 常用解码/分析工具；
- **合规不能忽视**：这是和 CTF 差异最大的一块，《密码法》、商用密码应用安全性评估（密评）的基本概念值得专门看；
- **练手平台**：先刷 CTF 的 Crypto 方向找手感，见 [CTF 学习资源](CTF竞技/学习资源.md)；
- **校赛组织者**：提前规划报名队伍数（记住"晋级数 ×2 ≤ 报名数"），给系统锁定留出至少一周缓冲改状态、交材料。
