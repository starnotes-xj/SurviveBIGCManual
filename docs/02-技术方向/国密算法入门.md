# 国密算法入门：SM 系列与国密 SSL

> **面向人群**：从没接触过国密的备赛选手。读完能回答三个问题：国密是什么、常见的有哪些、各自基于什么实现。
> 文末与 [ISCC真题复盘卷](ISCC密码安全赛真题卷.md) 第二题（国密 SSL VPN 流量分析）逐问对照。
> 文中 SM3/SM4 示例均用 `pip install gmssl` 实测。

## 一、"国密"是什么

**国密 = 国家密码管理局主导制定的商用密码（"商密"，SM = ShangMi）算法体系**，用于替换 RSA / AES / SHA 系列的自主可控算法。1999 年起陆续发布；2020 年《密码法》施行后地位法定化。标准编号有两套并存：

- 行业标准 **GM/T**（如 GM/T 0003-2012）
- 国家标准 **GB/T**（内容基本一致，如 GB/T 32918-2016）

速记对照：GM/T 0002→GB/T 32907（SM4）、GM/T 0003→GB/T 32918（SM2）、GM/T 0004→GB/T 32905（SM3）。

## 二、算法家族速览

| 算法 | 类型 | **基于什么实现** | 关键参数 | 典型用途 |
|---|---|---|---|---|
| SM1 | 对称分组 | **算法未公开**，仅以芯片实现 | 128 位分组 / 密钥 | 国密卡、安全芯片 |
| SM2 | 非对称（ECC） | **椭圆曲线离散对数问题（ECDLP）** | 256 位素域曲线 sm2p256v1 | 签名、密钥交换、公钥加密 |
| SM3 | 密码杂凑 | **Merkle–Damgård 迭代结构**，64 轮压缩 | 输出 256 位，分组 512 位 | 完整性、签名配套哈希 |
| SM4 | 对称分组 | **32 轮 Feistel 变体** | 128 位分组 / 128 位密钥 | 数据加密（对标 AES） |
| SM9 | 非对称（标识密码 IBC） | **双线性对（pairing）**，BDH 类难题 | 256 位 BN 曲线 | 标识即公钥，免证书 |
| ZUC（祖冲之） | 序列密码（流密码） | **16 级 31 位 LFSR + 非线性函数 F** | 128 位密钥 + 128 位 IV | 4G/5G 空口加密 |

**考试高频一句话**：SM2 基于 ECDLP；SM3 出 256 位、64 轮；SM4 是 128 位分组 32 轮；SM9 靠双线性对、标识当公钥；ZUC 用在 4G/5G（EEA3/EIA3）。

## 三、三大主角的原理

### SM2：椭圆曲线公钥密码（签名/交换/加密三合一）

- **数学基础**：椭圆曲线离散对数问题——已知基点 G 和点 kG，求标量 k 在计算上不可行。曲线上点的"加法"有几何定义，标量乘 kG = 把点加重复 k 次。
- **具体曲线**：256 位素域曲线，方程 `y² = x³ + ax + b`（取 a = p−3），标准曲线名 **sm2p256v1**，OID **1.2.156.10197.1.301**——真题抓包证书里那串 `2a811ccf5501822d` 就是这个 OID 的 DER 编码。
- **一个标准三件事**（GB/T 32918 分四部分）：
  - 第 2 部分：数字签名（哈希用 SM3）；
  - 第 3 部分：**密钥交换协议**——真题选项里那句 `U or V = [(dA + x̄1·rA)(dB + x̄2·rB)]G`（h=1）就出自这里；
  - 第 4 部分：公钥加密（KDF 派生密钥 ⊕ 明文 + SM3 摘要校验的混合加密）。
- **与 RSA 对比**：RSA 背后是大整数分解难题，SM2 背后是 ECDLP。同为 ~128 位安全强度，RSA 要 3072 位密钥，SM2 只要 256 位。
- **双证书体系**（国密 SSL 特色，真题抓包直接可见）：每个实体有**两张证书**——签名证书（sig，密钥对自产，用于签名）+ 加密证书（enc，密钥对由密钥管理中心生成托管，用于传递协商秘密）。真题里的 `sm2-site-sig` / `sm2-site-enc`、`sm2-user-sig` / `sm2-user-enc` 就是这两对。

### SM3：密码杂凑（对标 SHA-256）

- 与 SHA-256 同族：消息填充后按 **512 位分组**迭代压缩，**64 轮**，输出 **256 位**摘要；差别在消息扩展与置换函数（P0/P1、常量）细节。
- 标准测试向量（实测）：`SM3("abc") = 66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0`
- 用途：SM2 签名的哈希、密钥派生（KDF）、HMAC、完整性校验。

### SM4：分组密码（对标 AES）

- **128 位分组 / 128 位密钥**，**32 轮 Feistel 变体**（每轮以 32 位字为单位迭代轮换），S 盒非线性 + 线性扩散 `L(B) = B ⊕ (B<<<2) ⊕ (B<<<10) ⊕ (B<<<18) ⊕ (B<<<24)`。
- 工作模式与 AES 相同：支持 ECB/CBC/CTR/GCM（国密 SSL 里用 CBC 或 GCM）。
- 落地：金融 IC 卡 PBOC 3.0、国密 VPN 数据通道加密。

### SM9 与 ZUC（了解即可）

- **SM9（标识密码 IBC）**：不需要证书——**用户的标识（邮箱、手机号）直接当公钥**，私钥由密钥生成中心 KGC 用主密钥签发，省掉整个 PKI 证书链。数学基础是**双线性对** e(P,Q)（256 位 BN 曲线），安全性归结为双线性 Diffie–Hellman（BDH）类难题。
- **ZUC（祖冲之）**：序列密码。128 位密钥 + 128 位 IV，内部 16 级 31 位 LFSR + 非线性函数 F 输出密钥流，与明文异或即加密。3GPP 标准化后用于 4G LTE（EEA3 加密 / EIA3 完整性）并延续到 5G。

## 四、国密 SSL：GM/T 0024 与 TLCP（真题第二题主场）

两代协议标准：

- **GM/T 0024-2014《SSL VPN 技术规范》**：最早的国密 SSL，record 层版本号 **0x0101**；
- **GB/T 38636-2020《信息安全技术 传输层密码协议（TLCP）》**：国标升级版，结构与 0024 一脉相承，抓包里 record 版本仍是 0x0101。

### 密码套件表（真题 0xE011 / 0xE013 的出处）

| 套件号 | 名称 | 密钥交换 | 认证 | 数据加密 | 杂凑 |
|---|---|---|---|---|---|
| **0xE011** | ECDHE_SM4_CBC_SM3 | ECDHE（双方临时密钥） | 双向 | SM4-CBC | SM3 |
| **0xE013** | ECC_SM4_CBC_SM3 | **SM2 密钥交换协议**（GM/T 0003.3） | 服务端为主（可要求客户端证书） | SM4-CBC | SM3 |
| 0xE033 | ECCC_SM4_CBC_SM3 | SM2 加密证书（ECCC） | 双向 | SM4-CBC | SM3 |
| 0xE051 / 0xE053 | 对应 GCM 变体 | 同 ECDHE / ECC | 同上 | SM4-GCM | SM3 |

标准共定义 12 个套件，另有 IBSDH/IBC（标识密码）与 RSA 系列（见标准附录）。真题抓包里客户端就同时提供了 `e013 + e033`。

补充：TLS 1.3 也有国密套件——**RFC 8998**：TLS_SM4_GCM_SM3 {0x01,0x02}、TLS_SM4_CCM_SM3 {0x01,0x03}。

### 握手流程（对照真题抓包逐步定位）

1. **ClientHello**：报版本 0x0101、客户端随机数、支持的套件列表；
2. **ServerHello**：从列表中选定一个套件（真题数据 2 里客户端给了 `e013+e033`，服务端选定 **e013**）；
3. **Certificate**：服务端发证书链——注意是**签名证书 + 加密证书两张**，后面跟 CA 根证书；
4. **CertificateRequest**（可选）：要求客户端出示证书 → 客户端回 **Certificate + CertVerify**。有这条消息 = **双向认证**，没有 = 单向认证（真题两份数据都有 → 都是双向）；
5. **ServerKeyExchange / ClientKeyExchange**：密钥交换核心——ECDHE 套件的 SKE 是 65 字节临时 SM2 公钥（`04‖X‖Y`）+ SM2 签名；**CKE 里的 65 字节 `04‖X‖Y` 客户端临时公钥就是"计算预主密钥所需的重要数据"**（真题第 2 问答案）；
6. 双方计算**预主密钥**：RSA 类套件 = 客户端生成 **48 字节**；ECC 套件 = SM2 密钥协商输出 **16 字节、双方共同产生**（真题第 3 问）；再经 SM3 派生主密钥与会话密钥；
7. ChangeCipherSpec + Finished 收尾，之后 AppData 全部走 SM4 加密。

### 握手消息 type 对照：过滤器里的"门牌号"

`tls.handshake.type` 的取值是**协议常量**（规范写死，任何 pcap 都一样）；套件号则是 ServerHello 载荷里的**协商结果**，每个 pcap 可能不同——**type 用来"找"消息，suite 用来"读"结果，不存在"套件的 type"**。

| type | 消息 | 载荷要点 |
|---|---|---|
| 1 | ClientHello | 支持的套件列表 |
| 2 | ServerHello | **选定的套件号** |
| 11 | Certificate | 证书链（国密双证书） |
| 12 | ServerKeyExchange | 临时 SM2 公钥 + 签名 |
| 13 | CertificateRequest | 要求客户端证书（双向信号） |
| 14 | ServerHelloDone | — |
| 16 | ClientKeyExchange | **65 字节临时 SM2 公钥** |
| 15 | CertVerify | 客户端握手签名 |
| 20 | Finished | 加密完成校验 |

所以 tshark 过滤器"为什么一会儿写 2、一会儿写 16"：想知道**用了什么算法** → 找 ServerHello（type 2）读套件；想拿**预主密钥原料** → 找 ClientKeyExchange（type 16）切临时公钥；判**单向/双向** → 数 13/11/15 是否出现。详细推导见知识库 [#589](https://bigcctf.org.cn/wiki/589) 第 5–7 节。

### ECC 套件 vs ECDHE 套件（真题第 1、4 问的理论来源）

| | ECC（0xE013） | ECDHE（0xE011） |
|---|---|---|
| 密钥交换 | SM2 密钥交换协议（GM/T 0003.3，`U = [(dA + x̄1·rA)(dB + x̄2·rB)]G`，h=1） | ECDHE 临时密钥交换 |
| 预主密钥 | **16 字节、双方共同产生** | 双临时密钥协商，具备前向安全 |
| 身份认证 | 校验证书是防中间人的唯一手段——**不验证书即可 MITM**（真题第 4 问 e） | 同左 |

真题第 4 问的判断速记：已知随机数缺私钥 / 已知私钥缺随机数 → 都算不出 U/V；从 U/V 反推另一方私钥 = 椭圆曲线离散对数，不可行。

## 六、工具上手

- **GmSSL**：关志的开源国密工具箱，命令行自带 sm2/sm3/sm4 子命令；
- **Tongsuo（铜锁）**：OpenSSL 的国密分支，可搭国密 TLS 服务；
- **Python `gmssl` 库**（`pip install gmssl`，纯 Python 无依赖）：

```python
from gmssl import sm3, sm4

print(sm3.sm3_hash(list(b"abc")))
# 66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0（标准测试向量）

key = bytes.fromhex('0123456789abcdeffedcba9876543210')
c = sm4.CryptSM4(); c.set_key(key, sm4.SM4_ENCRYPT)
ct = c.crypt_ecb(b'ISCC GuoMi test!')       # SM4-ECB 加密
d = sm4.CryptSM4(); d.set_key(key, sm4.SM4_DECRYPT)
print(d.crypt_ecb(ct))                       # 解密还原
```

流量分析侧：**Wireshark 4.0+ 原生支持 TLCP**（GB/T 38636，360 贡献上游）——`tls.handshake.type`、`tls.handshake.ciphersuite` 字段直接可用（实测 ServerHello 直接给出 `0xe011`/`0xe013`），但 CKE/SKE 载荷内部不深解析（"Ciphersuite not implemented"），要抽 CKE 里的 65 字节临时公钥仍按本文与真题卷的"手工切包 + record 解析"处理（record 结构与 TLS 同构：type、version、length 三段头）。连国密 TLS 的现成命令行：Tongsuo 的 `openssl s_client -tls1_3 -ciphersuites TLS_SM4_GCM_SM3`（RFC 8998）或 TLCP 双证书 `-cert/-dcert`；GmSSL 的 `gmssl s_client -gmtls`。
