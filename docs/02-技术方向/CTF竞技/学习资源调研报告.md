## 七、迁移执行记录一：ROP Emporium → Re:Pwn

**流程**：官方打包下载（rop_emporium_all_challenges.zip，31 个架构包）→ 抓取 8 个题面页原文 → WSL + pwntools 逐题打验证可行解（`rop_emporium_migration/solve/solve_all.py` **8/8 PASS**）→ 编写中文题解 → 部署（建题 hidden→附件→answer→checker→hint→publish→wiki→判题验证）。

**平台结果**（game 6「Re:Pwn—从零开始的漏洞利用生活」）：

| # | 题名 | 平台 id | 验证 | 考点 |
|---|---|---|---|---|
| 1 | ret2win | 423 | OK | 栈溢出覆盖返回地址 + movaps 栈对齐 |
| 2 | split | 424 | OK | ret2libc（system + "/bin/cat flag.txt"） |
| 3 | callme | 425 | OK | PLT 连续调用 + pop rdi/rsi/rdx |
| 4 | write4 | 426 | OK | 任意写原语 mov [r14], r15 |
| 5 | badchars | 427 | OK | 坏字符（x g a .）+ XOR 编码/原理解码 |
| 6 | fluff | 428 | OK | xlatb/bextr/stosb 稀缺 gadget 组合 |
| 7 | pivot | 429 | OK | 栈迁移 + puts 泄漏 libpivot 基址 |
| 8 | ret2csu | 430 | OK | __libc_csu_init 两段 gadget + 无害调用目标选 fini_array |

每题配置：官方题面原文（描述）+ 官方引导段（提示，cost 0）+ 中文完整题解（answer + wiki 文章）+ `ROPE{...}` checker；判题验证 = 错 flag 拒绝 ✓ 对 flag 通过 ✓。

**过程中踩的坑（对后续迁移有用）**：
1. 新版 glibc 的 `system`/`fopen` 有 movaps 栈对齐要求——`ret2win`/`split` 直接跳会崩，链里补一条独立 `ret`。
2. write4 的 csu 在 0x400630（pop rdi=0x400693），与 badchars/fluff 的 0x400640（0x4006a0/0x4006a3）不同——各二进制要独立扫 gadget（capstone 非对齐扫描脚本 `solve/gadget_scan.py`）。
3. fluff 的 pwnme 在 read 后调 puts，破坏 rax——不能依赖 read 返回值控制 al，用 `mov eax,0; pop rbp; ret`(0x400610) 归零起步。
4. pivot 的 read 无换行语义：`sendline` 残留的 `\n` 会被下游 read 提前吃掉造成错位——全程 `p.send` + 每次 read 后用输出同步；真实链要放在 read#2 覆盖区（bigbuf+0x10..0x50）之外。
5. 平台 hint 创建必须带全字段 `{id, created_at, challenge_id, content, cost}`，只发 `{content, cost}` 会 422（`fix_hints_rop.py` 已补齐 8 条）。

**本地文件**：
- 验证脚本：`rop_emporium_migration/solve/solve_all.py`（8/8 PASS）、`solve/gadget_scan.py`
- 部署脚本：`rop_emporium_migration/deploy_rop.py`、`fix_hints_rop.py`、`deploy_rop_report.json`
- 题解存档：`rop_emporium_migration/writeups/*.md`（8 篇）

**后续迁移建议（优先级）**：① ImaginaryCTF 官方开源题库（✅ 已完成，见第八节）→ ② Flare-On 归档（逆向进阶）→ ③ picoCTF（新人梯度）→ ④ vulhub/Juice Shop 部署到服务器作为 Web 实操区（需开端口，属于"在线服务型"题）。
