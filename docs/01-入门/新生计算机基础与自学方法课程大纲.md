# 新生计算机基础与自学方法课程大纲

> [查看配套讲义：每节课的解释、演示、练习与核对要点](新生计算机基础与自学方法讲义.md)

> 面向刚入学、计算机基础差异较大的同学。这不是“软件安装清单”或四节速成课，而是一条从会使用电脑，到理解计算机、能编程、能协作，最终能自主学习的入门路线。每个知识点都回答“为什么”，再教“怎么做”。

## 一、课程目标与授课方式

学完后，同学应能：

1. 用键盘、快捷键、文件管理器和浏览器完成常见学习任务，分清文件名、扩展名与文件内容。
2. 解释网络中常见的“地址、下载、上传、带宽、网速、延迟”，并能做简单单位换算。
3. 把 GitHub 当作“开源项目的发现与协作平台”：会找项目、看 README 和许可证、辨别下载入口，而不是看到代码就盲目运行。
4. 管理 GitHub、Google 等学习账号；在具备条件时完成注册、验证与账号恢复信息配置。
5. 编写、运行、修改简单的 C/C++ 程序，并能读懂编译报错的基本位置。
6. 面对陌生字符串或工具，不凭“像”下结论，而是提出假设、寻找判据、做可重复的验证。
7. 理解操作系统、软件、进程、命令行、数据表示的基本关系；能根据报错定位问题，而不依赖别人远程代操作。
8. 保护账号和作品，能识别可疑下载、钓鱼页面与失效信息，知道如何备份和恢复。
9. 用文档、Issue、PR 和适当的 AI 工具协作学习，能够说明哪些内容已经验证、哪些只是猜测。

**每个主题固定采用同一节奏：**先给真实任务 → 让同学说出猜测和依据 → 教一个最小概念 → 当场操作验证 → 记录“我如何知道” → 留一个变式题。讲授时间尽量少于动手和讨论时间。

## 二、建议安排（4 次启动课 + 8 次拓展课，每次约 90 分钟）

前 4 次课让完全零基础的同学先能动手；后 8 次课根据社团活动、课程进度分周开展。**不要把 12 次课压成一场工具演示。**条件有限时，优先完成第 1–4 次及第 5、6、8、12 次，其他主题做工作坊或课后任务。

| 课次 | 主题 | 核心内容 | 当堂产出 |
|---|---|---|---|
| 第 1 次 | 电脑不是黑盒 | 打字与快捷键；文件、路径和扩展名；浏览器、搜索与信息核验 | 保存一份带截图和来源链接的学习笔记 |
| 第 2 次 | 网络与账号 | 网页如何打开；带宽、速率和延迟；GitHub/Google 账号；校园平台与 OCS | 做一次网络单位换算，建立账号与恢复清单 |
| 第 3 次 | GitHub 与协作 | 把 GitHub 当“应用商店”来逛；README、Release、Issue；Git/Fork/分支/PR | 给课程练习仓库提交一个小 PR |
| 第 4 次 | 编程与证据 | C/C++ 最小程序；编译、运行、报错；进制与 Base64 的识别和验证 | 运行一个程序，并完成“猜测—验证—结论”记录 |
| 第 5 次 | 电脑内部与命令行 | 硬件、操作系统、进程、路径、权限、终端；查看和运行程序 | 用终端定位文件、运行命令并解释输出 |
| 第 6 次 | 软件与开发环境 | 安装包、源代码、依赖；环境变量及 PATH；编译器、编辑器；卸载与回退 | 解释“命令找不到”的原因，搭建并复现一个最小环境 |
| 第 7 次 | 数据到底是什么 | bit/byte、二/十/十六进制、文本编码、图片格式；编码、压缩、哈希、加密 | 解释同一份数据的不同表示并完成对照实验 |
| 第 8 次 | 网络排障与安全 | HTTP、DNS、Cookie、缓存；钓鱼、密码管理、备份、恶意下载 | 排查一次模拟故障，写一份账号与文件保护方案 |
| 第 9 次 | 文档与效率 | Markdown、表格、PDF、截图、文件命名、云同步与版本；资料整理 | 写一篇他人可照做的图文操作文档 |
| 第 10 次 | 程序再进一步 | 函数、数组/字符串、调试器、测试用例、边界条件、简单复杂度 | 找出并修复一个有测试用例的 C/C++ 小程序错误 |
| 第 11 次 | 开源协作进阶 | Issue、许可证、提交信息、冲突、审查反馈；维护项目的礼仪 | 复现一个问题，提交可审查的 Issue 或 PR |
| 第 12 次 | AI 与独立探索 | 把 AI 当助手而非答案；读文档、检索、实验、复盘与求助 | 独立完成一个小项目或专题调查并展示证据链 |

> 可按设备、网络和注册情况拆成更多次课。账号注册、下载安装、PR 合并不作为同一时段必须完成的硬指标；没注册成功的同学可先用教师演示账号或截图完成识读练习，后续自行补齐。每次课最多引入少量新术语，始终让同学解释操作背后的机制。

## 三、各课内容与练习

### 第 1 次：基本操作与信息入口

1. **打字与输入**：中英文切换、大小写、数字和常用符号；强调代码中的英文标点、空格、换行。短练习：准确输入一段含路径、网址和命令的文字，而不只追求速度。
2. **常用快捷键**：`Ctrl+C/V/X/Z/S/F`，`Alt+Tab`，截图和浏览器新标签页；讲清“复制的是文字、文件，还是路径”。练习：只用键盘完成复制、查找、保存和窗口切换。
3. **文件系统**：文件与文件夹、绝对/相对路径、重命名、显示扩展名；`.txt`、`.md`、`.pdf`、`.zip`、`.exe`、`.c`、`.cpp`、`.h`、`.png`、`.jpg` 等常见扩展名。强调扩展名是线索，不是文件真实格式或安全性的证明。练习：显示扩展名，比较 `report.pdf`、`report.pdf.exe` 和改名后的文件。
4. **搜索与判断**：把问题拆成关键词，优先看官方文档、项目 README 与可复现示例；核对版本、发布日期和适用系统。练习：查一个未知快捷键，记录“搜索词—来源—验证动作—结论”。

### 第 2 次：网络常识、账号与校园场景

1. **网络路线图**：设备 → 路由器/校园网 → DNS（域名找地址）→ 服务器 → 浏览器；区分网址、域名、IP、网页和文件下载。以“打开一个网页失败”为例，逐层排查是网络连接、DNS、站点还是账号问题。
2. **带宽与体验**：`b` 是 bit，`B` 是 byte，理论上 `8 bit = 1 byte`；`100 Mbps ÷ 8 ≈ 12.5 MB/s` 是理想上限估算，不等于实际下载速度。区分带宽、吞吐量、延迟、丢包；让同学解释为什么“测速快但游戏卡”或“下载慢”并不矛盾。
3. **学习账号**：说明 GitHub、Google 账号各自用在什么场景；演示注册流程的关键步骤、邮箱验证、强密码、双重验证和恢复方式。由同学自己输入密码与验证码，教师不收集凭据。账号开通要求以当时页面和学校网络条件为准。
4. **校园平台与 OCS**：先认识课程平台的正常学习流程、任务状态和截止时间，再介绍仓库中提到的 OCS 工具及其 README/适用平台。区分“辅助管理学习任务”与“替自己完成课程要求”；涉及签到、考核、自动答题等功能时，以课程和平台规则为准，不把脚本结果当作已完成学习的证明。

### 第 3 次：把 GitHub 用起来，再理解 PR

1. **先会“逛”**：从具体需求出发搜索项目，读仓库简介、README、文档、许可证、最近维护情况和 Issues；识别源代码、Release 安装包、网页演示与依赖要求。GitHub 像“应用商店”是便于入门的比喻，但项目质量、安全性和可运行性需要自己核验。
2. **先会“用”**：选一个公开、适合新手的工具，说明“我解决什么问题—支持什么系统—从哪里获取—如何卸载或回退”。不要把 `Code → Download ZIP` 当成所有项目的安装方法。
3. **再会“改”**：用一张图讲清本地仓库、远程仓库、Fork、分支、提交、推送和 Pull Request。PR 是“请求维护者审查并合并更改”，不是改完自动进入主分支。
4. **实操闭环**：阅读本仓库的[提交 PR 指南](../04-账号与工具/GitHub注册与使用/提交PR.md) → Fork 练习仓库 → 建分支 → 修改一处错别字或补充一个可验证的链接 → 查看 diff → 提交 → 开 PR → 回应一次审查意见。没有账号的同学先对比变更并写 PR 标题和描述。

### 第 4 次：C/C++ 入门与“凭什么这么判断”

1. **最小程序**：源文件 → 编译器 → 可执行程序 → 运行结果；示范 `Hello, world!`、变量、输入输出、条件和循环，解释 `main`、分号、花括号。先让每个人亲手改一个输入或输出，再引入更多语法。
2. **错误是线索**：分别展示语法错误、编译错误、运行结果不符合预期；让同学找“文件、行号、报错文本、最小复现”，而不是整段截图后等待别人代修。
3. **进制不是看见字母就能断定**：十六进制的合法数字是 `0–9` 和 `A–F`（或 `a–f`）；出现 `G` 就不是普通十六进制数字。`1A` *可能* 是十六进制数，也可能是普通文本或编号；`0x1A` 是常见的明确写法。若把文本当十六进制字节串，还要检查长度、分隔符和解码后内容。例如 `4869` 按十六进制字节解读是 `48 69`，对应文本 `Hi`；但这一解释仍要由上下文支持。
4. **Base64 也不是“一眼定案”**：标准 Base64 常见字符集是 `A–Z a–z 0–9 + /`，末尾可有 `=` 填充；URL 安全变体常用 `- _`。字符集匹配只能产生“候选假设”，很多普通字符串也符合。进一步看长度、填充、出现的上下文，再尝试解码；成功解码出字节也不必然证明原文就是可读文字，更不能把编码误当加密。
5. **对照实验**：把 `4869`、`SGk=`、`AB12`、`hello`、`SGk` 分组；每组写出“可能是什么、支持/反对证据、下一步如何验证”，再用工具实际解码。允许多个解释并存，重点奖励有证据的推理，不奖励抢答术语。

### 第 5 次：电脑内部、操作系统与命令行

1. 用“程序存储在磁盘上，运行时成为进程并使用内存和 CPU”解释硬件、操作系统与应用的分工；区分文件大小、内存占用和磁盘空间。
2. 看懂路径、当前目录和文件权限，先知道“程序在哪里、我现在在哪里”。Windows 下练习 `pwd`（PowerShell）、`cd`、`dir`、`Get-Content`；可对照 Linux 的 `pwd`、`cd`、`ls`、`cat`，强调先确认所处目录和命令作用再执行。
3. 实验：同一个程序在文件管理器和终端中分别打开，观察工作目录、输入输出和报错位置；回答“为什么双击闪退时终端仍能看到错误”。

### 第 6 次：软件从哪里来，为什么会“在我电脑上不能用”

1. 区分官网、项目仓库、Release、安装包、便携版、源代码和依赖；理解操作系统、CPU 架构、版本、权限与网络都会影响安装。
2. 用一个小工具讲清编辑器、编译器、运行时和环境变量各自做什么；演示“命令找不到”与“代码编译失败”是不同故障。
3. 练习：按官方 README 搭建环境，记录版本、安装来源、验证命令、实际输出和卸载/回退方式。两人互换笔记，检验别人能否复现。

#### 环境变量与 PATH：必须真正讲透的一段

- **先讲原理**：环境变量是进程运行时可读取的“名字 → 值”。程序启动时通常从父进程继承一份环境；修改系统设置后，旧终端未必会自动更新。环境变量不是文件，也不等于安装软件。
- **再讲范围**：临时设在当前 PowerShell 窗口的变量、当前用户的持久变量、所有用户的系统变量，作用范围和生效时机不同。把个人工具的目录加到用户 PATH 通常就够了；不要为了省事随意改系统范围。
- **再讲 PATH**：在终端输入 `git` 时，终端要定位相应的程序；PATH 列出可搜索的目录。加入的是**可执行文件所在目录**，不是文件名，也不是任意下载目录。PATH 解决“在哪里找程序”，不解决“程序自身能否运行、依赖是否齐全、代码是否正确”。
- **区分三个容易混淆的东西**：`C:\Tools\bin\app.exe` 是程序的完整路径；`C:\Tools\bin` 可以是 PATH 中的一项；当前工作目录是程序读写相对路径文件时的起点。把三者混为一谈，是很多“在我的电脑上不能用”的来源。
- **安全演示（不改持久设置）**：在 PowerShell 先运行 `$env:COURSE_DEMO = 'hello'`，再运行 `$env:COURSE_DEMO` 观察输出；从开始菜单另开终端，检查临时变量是否存在，再从原终端启动子进程比较结果。用 `$env:PATH` 查看当前进程的 PATH，用 `Get-Command git` 或 `where.exe git` 查看实际命中的程序（如未安装 Git，就换成已安装的程序）。说明变量的可见范围与进程继承有关，而不是简单认为“所有新终端都一样”。
- **排障顺序**：先确认程序确实已安装 → 找到可执行文件 → 用完整路径试运行 → 查看终端实际找到哪个程序及其版本 → 再判断是否需要调整 PATH → 重新打开终端验证。修改前保存原值；不要覆盖整条 PATH，不要把密码或令牌放进课堂截图/笔记。
- **延伸阅读**：[手册中的 Windows PATH 设置步骤](../03-工具与问题/Windows常见问题/添加环境变量PATH.md)。课堂重点是理解与诊断，图形界面的点击步骤可课后按文档操作。

**当堂问题：**“我明明装了编译器，为什么输入命令提示找不到？”“为什么同一命令在两个终端运行的是不同版本？”“为什么程序找得到，却仍然读不到 `data.txt`？”要求分别用安装位置、PATH 顺序和工作目录解释，并用实际命令验证。

### 第 7 次：数据表示与格式

1. 从开关状态引出 bit、byte、二进制，再解释为什么十六进制适合简写二进制；做 `0x41`、十进制 `65`、二进制 `01000001` 的对应练习。
2. 区分字符与字节：ASCII、UTF-8、乱码、换行符；解释为什么同一个“字”在不同编码下占用的字节不同。
3. 区分“表示/编码”“压缩”“哈希”“加密”：Base64 方便传输字节，不负责保密；哈希便于校验或建立摘要，通常不能像编码那样直接还原；加密依赖密钥。用同一份短文本做四种处理，记录能否逆向恢复及需要什么条件。
4. 练习：比较文件扩展名、文件头、打开方式与实际内容；回答“把 `.png` 改名为 `.jpg` 为什么不等于格式转换”。

### 第 8 次：网络排障、账号安全与备份

1. 把“打不开网页”拆为本机连接、DNS、服务器、浏览器缓存、登录状态等候选原因；浏览器开发者工具只做观察，不要求新生立即掌握全部协议细节。
2. 解释 HTTP 请求/响应、状态码、Cookie/会话，以及“已登录”和“网页能打开”为什么是两回事；通过同一网页在普通/无痕窗口的差异做观察。
3. 实例辨别相似域名、诱导下载、索要验证码的页面；账号使用独立密码和双重验证，恢复信息由本人妥善保存，不把凭据贴到截图、仓库或求助消息里。
4. 设计备份：重要文档至少保留另一份独立副本，理解同步不等于备份；练习从备份恢复一份故意删除的练习文件。

### 第 9 次：文档、资料整理与学习效率

1. 以“一个月后自己还看得懂”为标准练习命名、目录、截图标注、链接保存和资料来源记录；区分原始资料、自己笔记和最终作品。
2. 用 Markdown 写标题、列表、链接、图片、代码块；知道何时交 `.md`、`.pdf`、文档或压缩包，不把文件格式当作可随意改后缀的标签。
3. 解释本地文件、网盘同步、Git 版本记录的不同用途；练习找回历史版本，避免 `最终版_真的最终版2`。
4. 任务：给同伴写一份“从零完成某操作”的短文档，让同伴按文档独立复现并指出缺漏。

### 第 10 次：C/C++ 与程序思维再进一步

1. 用输入、处理、输出组织小程序；函数用于拆分问题，数组/字符串用于处理多份数据，不急于堆语法。
2. 学会最小测试：正常值、空输入、边界值、错误输入；区分“能编译”“样例通过”“需求正确”。
3. 练习断点、单步、查看变量，比较调试器与随手打印；用一个有故意错误的程序完成“复现—定位—修复—回归测试”。
4. 只用直观例子介绍性能：线性扫描与重复嵌套循环在数据变大时的差异，不强迫初学者背复杂度符号。

### 第 11 次：真正参与开源协作

1. 阅读贡献指南、Issue 模板和许可证；理解“代码公开”不等于可以不看授权条件地复制、改名、再发布。
2. 学会提供可复现的问题报告：环境、操作步骤、预期、实际、日志和最小样例；不在公开 Issue 中泄露个人信息或密钥。
3. 对同一个小改动练习清晰的提交信息、查看 diff、回应审查意见；演示合并冲突不是“Git 坏了”，而是两处修改需要人决定如何组合。
4. 讨论协作礼仪：先检索重复 Issue、尊重维护者时间，拒绝把未经验证的 AI 输出批量提交给别人审查。

### 第 12 次：AI 辅助、自学路线与小项目

1. 教同学向搜索引擎、文档和 AI 清楚描述目标、环境、已尝试步骤；把 AI 产出的命令、引用和结论当待验证假设。
2. 比较“直接问答案”和“请解释推导、指出反例、给验证步骤”得到的学习效果；演示 AI 可能编造不存在的参数或链接，应回到官方文档和实际运行结果核对。
3. 让每人选一个贴近自己的小项目：整理课程资源、修订一篇手册、写一个 C/C++ 小工具、解释一次网络问题等；设定一周内可完成的最小成果。
4. 展示项目时固定回答四个问题：我解决什么问题？我参考了什么？我怎样验证？目前还有什么不确定？

## 四、贯穿全部课程的自学方法

给新生一张可反复使用的“问题卡”，每次遇到新问题都按同一顺序填写：

1. **说清目标**：我想完成什么？现在看到什么？预期与实际差在哪里？
2. **补齐上下文**：系统、软件版本、输入、操作步骤、完整报错、时间与来源是什么？
3. **提出不止一个假设**：例如“像 Base64”只是一个假设；还可能是随机标识、哈希片段或普通文本。
4. **找判据和反例**：哪些特征支持它？什么发现会推翻它？不要把“符合字符集”误写成“已证明”。
5. **做最小验证**：选一个可复现、低成本的测试；保存输入、命令/步骤和结果。先查官方文档与项目文档，再参考他人的经验。
6. **记录并表达**：写下结论、证据、仍不确定的地方。求助时附上已尝试的方法，而不是只说“这个怎么弄”。

**教师提问模板：**“你是怎么猜的？”→“这个特征是否也会出现在别的东西上？”→“如果你的猜测是对的，下一步应该观察到什么？”→“实际观察到了吗？”

## 五、结课小任务与评价

给出一个陌生开源项目和一段未知字符串，让同学独立完成：

- 找到项目的用途、官方使用说明、适用环境和获取入口，并说明判断依据。
- 说明该字符串可能属于哪些表示形式；给出支持与反对证据，实际验证至少一种解释。
- 修改练习仓库中的一个小问题，提交 PR 或准备一份完整的 PR 草稿。
- 写一段不超过 200 字的复盘：**我原来怎么想、证据改变了什么、下次我会怎么查**。

评价重点不是安装了多少软件、背了多少快捷键，而是能否独立完成一次“提问—检索—验证—记录—协作”的闭环。允许使用搜索和 AI，但要求展示来源、验证过程及自己的理解。

### 分层评价，避免把零基础同学甩下

| 层级 | 能做到什么 | 检查方法 |
|---|---|---|
| 入门 | 能完成操作，并说出文件、账号、网页和程序分别在哪里 | 现场完成任务，口头解释关键一步 |
| 合格 | 遇到变化能查资料、读报错、验证至少一种假设 | 提交问题卡与可复现步骤 |
| 进阶 | 能比较多种解释，考虑反例，帮助同伴复现或审查 | 提交小 PR、测试记录或教学文档 |

不要用打字速度、是否已有海外账号、是否能一次装好环境来评价理解能力。

## 六、课前准备

- 教师准备：练习仓库、可合并的小 Issue、演示用非个人账号、下载文件与扩展名样本、进制/Base64 对照样本、网络单位换算题、模拟报错、离线资料包及备份恢复样本。
- 学生准备：电脑、浏览器、可收邮件的邮箱、笔记工具；提前确认是否能访问课程平台与 GitHub。
- 备选方案：网络不可用时使用离线 README 截图、预先下载的样例仓库和纸面 PR/diff；账号未完成时先练识读与草稿，不让账号问题挡住方法训练。
