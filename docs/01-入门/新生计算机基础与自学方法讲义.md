# 新生计算机基础与自学方法讲义

> 配套[课程大纲](新生计算机基础与自学方法课程大纲.md)。这份讲义可以直接给新生阅读、投屏讲解和动手练习。每次课按“先试 → 解释原理 → 再试 → 说出证据”组织，不要求一次记住所有术语。

今天集中讲 C/C++ 时，使用[《C 与 C++ 基础语法及常用函数讲义》](C与C++基础语法及常用函数讲义.md)，内含完整可保存的程序和课堂练习。

## 上课前：我们到底要学会什么

计算机课不是背出一串快捷键或装齐一排软件。真正有用的能力是：**明确目标、观察现象、提出几种解释、找到能区分它们的实验、记录结果、再决定下一步**。例如“这串字符一眼看着像 Base64”，只能是猜测；必须问它满足什么规则、解码后是什么、有没有别的可能。

每人建立一份自己的学习记录，固定写五栏：**问题｜环境与输入｜猜测和依据｜验证步骤与原样结果｜结论及尚未确认的点**。课堂允许查资料和使用 AI，但必须能解释并复现自己的答案。

## 第 1 课：电脑操作、打字与文件

### 先讲清楚

- 输入法负责把按键转换为文字；代码中的括号、引号、分号、路径分隔符通常需要英文半角。让同学对照输入 `int main() { return 0; }`，观察中文标点为何会导致代码报错。
- “复制”与“移动”不是一回事。复制会留下原件；移动会改变文件位置。保存是把编辑器中的内容写入文件，关闭窗口前不保存会丢失改动。
- 文件有**名称、扩展名、内容、路径**四个不同概念。扩展名通常帮助系统选择打开方式，但不保证内容真是那个格式。把 `a.txt` 改名为 `a.jpg`，文字不会变成图片。
- 文件夹是组织文件的容器；绝对路径从磁盘/根目录写起，相对路径从“当前工作目录”算起。浏览器下载目录和代码所在目录不一定相同。

### 教师演示与学生操作

1. 让学生打开文件管理器，启用“显示文件扩展名”，建立 `course` 文件夹和 `notes.txt`，输入三行文字并保存。
2. 用 `Ctrl+C`、`Ctrl+V` 复制文字，用 `Ctrl+Z` 撤销，用 `Ctrl+S` 保存，用 `Ctrl+F` 查找；再用 `Alt+Tab` 在浏览器与编辑器之间切换。
3. 准备 `report.pdf`、`report.pdf.exe` 两个**仅作识别、不运行**的文件名，让学生指出最后一个扩展名，并讨论为什么只看图标容易误判。
4. 让同桌仅凭写下的路径找到 `notes.txt`，不允许说“就在桌面那个文件夹里”。找不到时补全盘符、文件夹名和扩展名。

**核对问题：**“改后缀是否等于转换格式？”答：不是，内容未改变。“`Ctrl+S` 保存到哪里？”答：保存到当前文件所指定的路径；新文件第一次保存时需要选择路径。

## 第 2 课：网络、账号和校园工具

### 网页为什么能打开

输入网址后，浏览器先得到要联系的服务器地址（通常涉及 DNS），建立连接，发送请求，服务器返回响应，浏览器再显示页面。这里至少有四层可能出问题：**本机是否联网、域名能否解析、服务器是否响应、登录是否有效**。网页打不开，不应立刻断定“账号坏了”。

**带宽算例：**运营商说的 `100 Mbps` 是每秒 100 兆**比特**；下载软件显示的 `MB/s` 通常是每秒兆**字节**。因为 1 byte = 8 bit，理想上限是 `100 ÷ 8 = 12.5 MB/s`。实际值受协议开销、服务器、Wi-Fi、共享网络等影响。延迟是一次交互需要等待多久，丢包是部分数据未成功送达；高带宽并不保证低延迟。

### 账号与校园场景

- GitHub 账号用于发现项目、保存仓库、提 Issue/PR；Google 账号可用于部分学习资源和服务。注册时自己处理邮箱验证、密码和恢复方式，不把密码、验证码或恢复码发给助教。界面以当时实际页面为准，详细步骤看[GitHub 注册与配置](../04-账号与工具/GitHub注册与使用/注册与配置.md)及[Google 账号常见问题](../04-账号与工具/Google账号/注册与常见问题.md)。
- 一个账号至少弄清：登录邮箱是什么、双重验证如何完成、丢设备后如何恢复。**验证邮件收不到**时，先检查邮箱地址、垃圾箱、网络和等待时间，不要反复盲目点击。
- 校园平台先学会看课程、任务、截止时间和完成状态。手册提到的 OCS 是辅助工具；使用前读其说明、确认平台和课程要求。课程内容仍要自己学，脚本显示“完成”不能代替理解，也不能据此推断教师端状态。

**课堂练习：**某同学测速显示 80 Mbps，下载器显示约 8 MB/s。他说“学校少给了 72 兆”。请指出单位错误：80 Mbps 理论约 10 MB/s，8 MB/s 可由实际损耗解释；还需排查服务器等因素，不能直接下结论。

## 第 3 课：把 GitHub 当“应用商店”，再学 PR

“应用商店”是一个入门比喻：先带着需求搜索，再看项目说明、系统要求、发布版本和用户反馈。但 GitHub 不是统一审核安装包的商店，仓库里的代码也不等于能直接安装。

### 实际阅读一个仓库

打开一个公开仓库后，按顺序回答：

1. **它解决什么问题？** 看简介与 README 的第一段，不从项目名猜。
2. **怎样使用？** 找安装、使用、示例、支持的平台和版本；有的项目有 Releases，有的需要编译，有的只是源码或文档。
3. **是否适合我？** 看许可证、最近维护、未解决 Issue、依赖条件。星标数可以参考，但不是正确性或安全性证明。
4. **遇到问题去哪问？** 先搜索已有 Issue 和文档；提问时附环境、步骤、预期与实际。

### PR 的完整故事

仓库是项目文件及历史；提交（commit）保存一次改动记录；分支让改动与主线暂时分开；Fork 是在自己账号下建立一份仓库；PR 是请求维护者**审查并合并**自己的分支。它不是“我已经改了，所以主项目自动变了”。

课堂用一个错别字练习：先读[本手册的 PR 指南](../04-账号与工具/GitHub注册与使用/提交PR.md)，再 Fork 练习仓库、建分支、只改一处、查看 diff、写清“为什么改”、提交 PR。审查时若被要求修改，就继续在同一分支更新，而不是重新开一堆 PR。

**不注册账号也能完成的练习：**教师给出变更前后两段文字，学生手写一个 PR 描述：问题是什么、改了什么、怎样核对、哪些地方没改。审查者只看 diff，判断描述是否可信。

## 第 4 课：第一段 C/C++ 程序和“报错是线索”

下面两段分别保存为 `hello.c` 和 `hello.cpp`。选择已安装的编译器；命令中的 `gcc`/`g++` 若找不到，先去第 6 课检查安装与 PATH。

```c
#include <stdio.h>
int main(void) {
    int age = 18;
    printf("明年 %d 岁\n", age + 1);
    return 0;
}
```

```cpp
#include <iostream>
int main() {
    int age = 18;
    std::cout << "明年 " << age + 1 << " 岁\n";
    return 0;
}
```

有 GCC 时，分别执行 `gcc hello.c -o hello_c.exe`、`g++ hello.cpp -o hello_cpp.exe`，再运行 `.\hello_c.exe` 或 `.\hello_cpp.exe`。**源文件是人写的文本；编译器把它转换为可运行程序；终端显示的是程序执行结果。**编辑器、编译器、终端不是同一个东西。

让学生把 `18` 改为其他数，预测输出再运行。再故意删掉一个分号，记录报错文件、行号和文字；最后恢复并重新编译。强调报错行号有时指向出错位置之后，不能只盯住该行。

**核对问题：**“修改了源文件但直接运行旧 `.exe`，为何结果没变？”答：必须重新编译，旧可执行文件不会自动更新。

## 第 5 课：操作系统、进程、目录与终端

磁盘保存文件，内存暂存正在使用的数据，CPU 执行指令；操作系统管理这些资源并提供文件、进程和设备接口。程序是磁盘上的文件，进程是程序运行中的实例；同一个浏览器程序可有多个进程。

在 PowerShell 里做下面的观察，不用管理员权限：

```powershell
Get-Location                 # 我现在在哪个目录
Get-ChildItem                 # 当前目录里有什么
New-Item -ItemType Directory -Name practice
Set-Location practice
'hello' | Set-Content note.txt
Get-Content note.txt
Get-Process | Select-Object -First 5 Name, Id
```

`note.txt` 是相对路径，所以会被创建在当前目录。把 `Set-Location practice` 省掉，再运行一次写文件命令，比较两个文件的位置。课程结束时只清理自己刚创建的练习目录，不要让学生照抄不理解的删除命令。

**核对问题：**“双击程序一闪而过，但在终端运行能看到报错，为什么？”答：终端通常继续显示程序的标准输出和错误输出，便于观察；双击窗口可能随程序结束关闭。

## 第 6 课：安装软件、环境变量、PATH 与工作目录

### 先画出关系

一个工具是否能用，至少有四个独立问题：**是否安装了程序 → 终端能否找到它 → 它的依赖是否齐全 → 它运行时能否找到所需文件**。PATH 只主要解决第二个问题。

环境变量是进程读取的“名字—值”。例如 `COURSE_DEMO=hello`；PATH 是其中一种特殊变量，里面有若干目录。当你输入程序名时，终端会根据自己的命令解析规则和 PATH 寻找程序。PATH 里放的是可执行文件所在的**目录**，不是把程序内容贴进去。

在 Windows 中区分三种范围：本次终端/进程里的临时变量、当前用户的持久变量、系统范围的持久变量。进程启动时会继承环境，所以修改持久设置后，旧终端通常仍拿着旧值。先从开始菜单开新终端验证；从旧终端启动的子进程可能继续继承旧值。

### 不改系统设置的实验

```powershell
$env:COURSE_DEMO = 'hello'
$env:COURSE_DEMO
$env:PATH -split ';' | Select-Object -First 5
Get-Command git -ErrorAction SilentlyContinue
where.exe git
```

第一行只修改当前 PowerShell 进程及其子进程可继承的环境；从开始菜单独立打开的终端一般看不到 `COURSE_DEMO`。如果没有安装 Git，最后两行找不到是预期现象，改查已经安装的程序即可。课堂不要求给系统 PATH 添加任何项。

**三个路径不要混淆：**`C:\Tools\bin\app.exe` 是程序完整路径；`C:\Tools\bin` 可能是 PATH 中的一项；`D:\course` 可以是当前工作目录。程序“找不到”与程序运行后“找不到 `data.txt`”可能分别由前两者和后者导致。

**排障演练：**先确认可执行文件实际存在；用完整路径运行；用 `Get-Command 工具名` 查看终端命中了哪个程序；运行 `工具名 --version` 核对版本；必要时再参考[Windows PATH 设置说明](../03-工具与问题/Windows常见问题/添加环境变量PATH.md)。修改持久 PATH 前保存原值，不覆盖整条变量。密码或令牌不写进公开笔记和截图。

## 第 7 课：为什么是十六进制，为什么“像 Base64”

### 从二进制推到十六进制

一个 bit 有 0/1 两种状态；4 个 bit 有 `2^4=16` 种组合，因此一个十六进制数字恰好代表 4 bit：`0–9` 表示 0–9，`A–F` 表示 10–15。8 bit（一个字节）就可用两个十六进制数字表示。`0100 1000` 分成 `0100=4` 与 `1000=8`，所以是 `0x48`；在 ASCII/UTF-8 中这一个字节对应字母 `H`。

看到只含 `0–9 A–F` 的 `4869`，只能说“它**可以**按十六进制字节解释”，分组 `48 69` 得到 `Hi`；它也可能是编号或普通文本。看到 `G` 则可以排除“只由普通十六进制数字组成”的解释。要综合字符范围、长度、前缀 `0x`、上下文和解码结果。

### 从字节推到 Base64

Base64 将连续字节按每 6 bit 分组，因为 `2^6=64`。标准字符表依次使用 `A–Z`、`a–z`、`0–9`、`+`、`/`；末尾可能用 `=` 填充到四字符一组。URL 安全变体常把 `+`、`/` 换成 `-`、`_`。

以 `Hi` 为例，两个字节 `0x48 0x69` 的二进制是 `01001000 01101001`。从左向右分成 `010010`（18）、`000110`（6）、`100100`（36，末尾补零），查表得到 `S G k`，再加一个填充字符得到 `SGk=`。因此看到 `SGk=` 有理由怀疑 Base64；**只满足字符集仍不构成证明**，还要尝试解码，并结合上下文判断解码后的字节是否合理。Base64 是编码，不是保密加密。

**动手验证：**

```python
import base64
print(bytes.fromhex("4869"))             # b'Hi'
print(base64.b64decode("SGk="))          # b'Hi'
print(base64.b64encode(b"Hi").decode())  # SGk=
```

讨论 `AB12`、`hello`、`SGk`：`AB12` 既符合十六进制字符规则，也符合 Base64 字符规则，仍不能确定用途；`hello` 长度模 4 余 1，不符合标准完整 Base64 编码长度；`SGk` 可能是省略填充的 Base64。解码出来是任意字节，也不代表它一定是文字。

## 第 8 课：网络排障、账号安全与备份

把“打不开网站”写成可检验的问题：其他网站能否打开？同一网站换设备能否打开？域名是否拼错？浏览器是否显示具体状态码？未登录和加载失败是不同现象。DNS 负责把域名解析为地址；HTTP 请求/响应负责交换网页数据；Cookie 等状态帮助网站识别会话，但不是“网站本身”。

**情景练习：**教师给出三张模拟截图：① 网络断开；② 页面可打开但提示登录过期；③ 下载按钮指向拼写相近的陌生域名。同学分别写出下一步最小验证，不能把三者都回答成“重装浏览器”。

保护账号：不同重要账户用不同密码；启用双重验证并保存恢复方式；不把验证码给“客服”；安装软件先看来源、签名/发布说明、所需权限。保护文件：同步能让多个设备保持相同状态，但误删除也可能同步过去；重要作品另留独立备份，并至少做一次恢复练习。

## 第 9 课：文档、截图、搜索与资料整理

一份别人能复现的操作文档至少包含：目标、适用环境、前提、步骤、预期结果、失败时如何定位、引用来源。截图要圈出相关区域，避免泄露邮箱、令牌和个人信息。文件名写内容与日期，而不是层层追加“最终版”。

Markdown 最小例子：

```markdown
# 问题：编译器命令找不到
环境：Windows / PowerShell / 编译器版本待确认
已尝试：运行 `Get-Command gcc`
结果：未找到命令
下一步：确认 gcc.exe 是否实际存在，再核对 PATH
```

**互测练习：**每人写一页“在自己电脑上找到某个下载文件并确认扩展名”的说明；同桌不口头提问，照文档操作。如果做不到，作者补充缺失的前提或步骤。评价文档是否可用，不评价排版花哨程度。

## 第 10 课：C/C++ 再进一步——函数、测试与调试

用小函数降低理解难度：

```cpp
#include <iostream>
int sum_to(int n) {
    int sum = 0;
    for (int i = 1; i <= n; ++i) sum += i;
    return sum;
}
int main() {
    int n;
    if (!(std::cin >> n) || n < 0) return 1;
    std::cout << sum_to(n) << '\n';
}
```

先预测输入 `0`、`1`、`5` 的输出：分别是 `0`、`1`、`15`。再让学生把 `i <= n` 故意改为 `i < n`，测试 `n=1` 与 `n=5`，观察边界错误；用调试器单步看 `i` 与 `sum` 的变化。说明“能编译”只表示语法等检查通过，不保证需求正确。

扩展提问：若 `n` 很大，`int` 可能溢出；若输入不是整数，程序应如何处理？这让学生知道测试除了常见值，还包括边界与无效输入。

## 第 11 课：Issue、许可证与协作反馈

找一个练习仓库中的问题，先复现，再写 Issue 草稿：

```text
标题：Windows 下运行示例时找不到 data.txt
环境：Windows、PowerShell、项目版本/提交号
步骤：1. ... 2. ...
预期：输出示例结果
实际：出现“找不到文件”；附完整报错
已排查：确认文件存在，比较了两个工作目录
```

读许可证时至少确认能否使用、修改和再发布，以及是否要求保留版权声明；“公开可见”并不等于随意复制。做 PR 时描述应与 diff 一致；收到审查意见要确认问题、修改并回复验证结果。冲突表示两边改到了相互影响的位置，需要人判断最终内容，而不是随便选“全部接受”。

**互评标准：**只凭 Issue 能否复现？只凭 PR 描述能否知道改动目的和测试方法？是否有私人数据需要删掉？

## 第 12 课：AI、检索与独立小项目

搜索与 AI 最有用的输入不是“帮我弄好”，而是：“我在 Windows PowerShell 中，运行 `gcc --version` 得到某个完整报错；已确认某路径有 `gcc.exe`；请给出两个可能原因、区分它们的最小检查命令，并解释每条命令预期看到什么。”这样的提问保留了问题与证据，也让答案可验证。

AI 可能给出不存在的参数、过期的界面或看似合理的错误结论。核对方法：回到官方文档、命令帮助、原始数据和实际运行结果；引用应能打开且支持对应说法。**能运行一次不等于理解，能解释失败时怎么查才是真会。**

结课时每人完成一个小项目：写 C/C++ 小工具、修订一篇手册、排查一个网络现象，或为同学整理一次可复现的工具安装过程。展示时按“问题 → 尝试过的假设 → 证据 → 结果 → 未解决点”叙述，不允许只放成品截图。

## 随堂答案与教师检查清单

| 问题 | 应听到的关键点 |
|---|---|
| 有数字和字母，为什么不能直接断定十六进制？ | 只允许 0–9/A–F；符合字符集只是必要线索，编号和普通文本也可能符合；看前缀、分组、上下文和解码结果。 |
| 为什么“像 Base64”？ | 观察字符集、长度/填充与上下文；按 6 bit 分组的规则解释来源；解码并判断字节是否合理，仍保留其他可能。 |
| 100 Mbps 为什么不是 100 MB/s？ | bit 与 byte 不同，理想换算要除以 8，实际还有损耗。 |
| 装了软件为什么命令找不到？ | 先确认程序确实存在，再看终端命令解析和 PATH；不能直接断定必须重装。 |
| 为什么换个终端环境变量就不一样？ | 进程在启动时继承环境；临时变量与持久用户/系统变量范围不同。 |
| GitHub 下载 ZIP、Release、Fork 有何区别？ | ZIP 通常是源码快照；Release 可能有发布产物；Fork 是为协作建立自己的仓库副本。 |
| 什么时候算“会了”？ | 离开教师演示后，能解释原理、独立复现、发现反例并记录证据。 |

每次课末尾让学生交一张“问题卡”，教师只检查三件事：**是否写清原始现象、是否有能区分猜测的验证、是否诚实标注不确定性**。课后根据问题卡补下一节课，而不是继续无差别堆术语。
